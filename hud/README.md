# 对局 HUD

扫描游戏画面，完整记录对局：双方每排的牌、进场 / 离场 / 移动、从手牌打出 / 召唤 / 生成、对方特殊牌、领袖技能、停牌、每手之后的双方总分；置顶小窗实时显示，一键导出对局簿能直接导入的 v2 对局代码。

只截屏幕上公开显示的画面：不改游戏、不读内存、不抓网络包。

## 安装（一次）

```bash
python -m pip install --user opencv-python mss numpy Pillow
python -m pip install --user torch torchvision --index-url https://download.pytorch.org/whl/cpu   # 可选：对方半场漏认补位（embed.py）
node hud/export_cards.js
python hud/build_db.py
```

`build_db.py` 从 gwent.one 下载卡图（约 130 MB）并建特征库，都在 `hud/cache/`（不提交）。卡牌数据更新（补丁、新牌）后重跑这两步。网络走 `HTTPS_PROXY`。

我方卡组：把卡组代码（`#GWDECK v2 …`）或对局簿备份文件路径写进 `hud/deck.txt`，我方就只认卡组里的牌（外加这些牌卡面上点名的衍生牌，如“无畏者”布朗温），手牌区的误识别进不来。

游戏内卡图模板：有的牌游戏里用另一版卡图（动态卡图、构图不同，如雷纳德·奥多），和 gwent.one 的图只对得上几个特征点，常认不出、估出的牌高偏大（被当成手牌）。从录像帧截下这张牌（卡框外沿）当模板，`Matcher` 载入时自动并入（只用卡框里面的画面，边框、菱形、图标每张牌都有，不学）：

```bash
python hud/learn_art.py 帧.jpg 牌名 x0 y0 x1 y1     # 框为画面比例；动态卡图从不同帧截 2–3 张
python hud/learn_art.py --list
```

## 实时使用

```bash
python hud/hud.py
```

- 游戏用**窗口模式**（程序按进程自动找 Gwent.exe 的窗口，窗口移动了也跟着走）。游戏窗口别被其他窗口挡住；小窗自己默认不出现在截图和录屏里。
- 小窗：比分和小局、对方已出的牌（解牌标红、召唤/生成标灰）、场面时间线。
- “导出对局代码”：复制对局簿 v2 代码，到对局簿“导入对局”粘贴，直接复盘。召唤记录带 `x.hud` 标记、离场 / 移动写成备注，方便核对。
  默认把画面上读到的每个单位战力（连续两帧一致）写成改战力记录，对局簿里的场面就是实际场面；`--no-sync` 关掉（核查推算引擎规则时用）。
- `--save-frames` 把扫描过的画面存下来（一局几百 MB），给离线分析、调参数用。

## 离线分析

```bash
python hud/record.py 40                          # 录游戏窗口（全分辨率；每秒看约 10 次，画面变了隔 0.3 秒存一张，右侧展示框出现时每 0.1 秒存一张）
python hud/video_frames.py 录屏.mp4               # 或者从录屏视频抽帧（iPad 4:3 也行）
python hud/export.py hud/cache/rec/<目录> 20261001 --jobs=4 --deck=hud/deck.txt --sync-power [--video=你的录屏.mp4]
node hud/replay_check.js hud/cache/rec/<目录>/game_v2.txt               # 喂给对局簿推算引擎，逐局出偏差报告
python hud/power_train.py hud/cache/rec/<目录>                           # 用白色数字重新训练战力模板
python hud/compare.py hud/cache/rec/<目录>/game.json 对局簿备份.json    # 和对局簿手记的同一局比较
python hud/timeline.py hud/cache/rec/<目录> 20261001                  # 只看时间线；人机对局会和游戏日志核对 AI 出牌
python hud/eval.py board hud/cache/rec/<目录> [--det]                    # 和人工核对的我方场面（<目录>/truth.json）比较
python hud/check_record.py hud/cache/rec/<目录>/game.json 对局代码.txt     # 和对局簿手记（v2 代码）逐条对照：打出 / 带出 / 领袖 / 指令和目标
```

**给用户待确认清单之前，先拿手记对照（`check_record.py`）**：HUD 能自己从卡面和画面推出来的，不该问用户。

导出同时写 `<目录>/review.html`：**待确认清单**，HUD 拿不准、要看录屏补的地方（领袖目标、效果目标、离场原因、对方单位是打出还是被带出、超出卡组张数被当成误认丢掉的“打出”），每条写“录屏时间 · 对局簿第 N 步”，附前后两帧截图。`--video=` 给自己的录屏（文件名带 UTC 时间，如 `20261001-0112-44.6374215.mp4`），记录和清单里的“录屏”时间就是这个视频的进度（误差 3 秒内）。

`truth.json`：`{"rounds": [["09:13:00", "09:14:42"], …], "me": [["09:15:48", "进场", "我方远程", "雷纳德·奥多"], …]}`，逐帧看画面核对我方两排每次变化（进场 / 离场）的时间，游戏日志里的 `CardLandingEffect` 时间可以对照。`eval.py board` 给出逐帧（离每次变化 3 秒以外）每排的对 / 多认 / 漏认、场上牌被当成手牌的帧数，以及时间线我方进场离场对上 / 漏 / 多出。扫描缓存 `scan.json` 存着分排前的原始检测（`det`），`--det` 用当前 `board.classify` 重新分排，调分排规则不用重扫。

## 做法

- **认牌**（`matcher.py` `board.py`）：SIFT 特征比对 gwent.one 卡图（外加游戏内卡图模板）。每个匹配点按它在卡图上的相对位置和缩放反推卡牌中心和高度，按中心聚成一张张牌（相邻同名牌能拆开；同一张卡图票数不到最强一簇 15% 的影子、和更强一簇重叠的去掉）。分排（`board.classify`）：中心低于 0.81 屏高是手牌；否则和这个位置的场上牌高（透视，近战 0.53 → 0.172、远程 0.775 → 0.21）比，大 1.3 倍以上是手牌（悬停、拖动），小于 0.6 倍或超过 0.45 屏高是假检测，其余按中心高度分四排。
- **对方半场子库**（`timeline.opp_matcher` / `op_faction`）：对方半场只在“对方阵营 + 中立 + 衍生牌 + 我方阵营（被抓过去的、我方潜伏牌、帝国外交创造的）”里认，展示框同样；
  我方半场（`mine_matcher`）= 卡组 + 卡组的战术牌（`tac=`）+ 衍生牌，知道对方阵营后再加对方阵营带“不忠”的牌（法师渗透者打在我方半场）；
  对方阵营由对方半场认出的非中立牌按票数投票（抽 40 帧，存 `scan_meta.json`；最多的不到 60% 就用全库），`HUD_OPP=0` 关掉做对照。
  两局重扫：手记对照对上 31 / 49（全库重扫 30 / 48），对方多认的猫、漏认的蟹蜘蛛毒液都好了。
- **回归**：`python hud/regress.py`（手记对照、我方逐帧、时间线、战力评估集、人机局 AI 出牌，和 `cache/regress_base.json` 比；`--save` 存基线、`--rescan` 重新认牌）。
  “推算核对点”：不同步战力的导出喂给对局簿推算引擎（`replay_check.js`，`TRACKER=` 换引擎），核对点对上几个——记录本身（落地战力、目标、来源、漏记的指令）对不对。
  2026-10-03 用修过侦察员的引擎：对尼弗迦德局 12/29（这轮修之前 2/28），旧的两局 4/31、4/35——HUD 记录离“喂给引擎就算对”还差得远。
- **右键看牌的全屏界面**（背景模糊，右边一张大卡，位置和展示框一样）：挡住了比分，读不出比分的帧不认展示框（2026-10-02 一局右键看了 5 次，以前记成对方打出大赦、熊化反应）。
  同一张展示框和上一次看到的间隔不到 6 秒算同一次（对方选目标、创造的三选一界面挡住几秒）。
- **看牌的大说明面板**（右键 / 长按看牌，里面有衍生牌的小图，会被认成场上的牌）：画面中间羊皮纸颜色占比 > 0.25（`detect.panel_ratio`）的帧当没录到。
- **时间线**（`timeline.py`）：按“排 × 牌名”记张数，带迟滞（进场要连续两次看到，离场要连续三次、至少 2.5 秒看不到）；同排同名牌离场后 40 秒内又出现当作识别闪烁；模糊的覆盖界面（调度、墓场、选牌；左侧场景清晰度 < 40，正常对局随棋盘皮肤 60–1000）和读不到总分的帧跳过；一大半牌同时消失、8 秒内出现模糊的过场画面 = 小局结束（没有过场就是真的离场，照常记）；只零星出现一帧的牌不累计“连续看到”。
- **打出还是召唤**：对方靠右侧展示框（对方打出的牌会放大展示不到 1 秒，`hud.py` 的展示线程每 0.15 秒看一次；特殊牌只能靠它）；我方可收集单位 / 神器落地算打出，手牌里消失的特殊牌算打出特殊牌；同排同名复制、刚打出“召唤”牌后几秒内进场的记成带 `via` 的召唤；刚打出“从牌组打出”的牌（水路突袭、骑士册封）带出的记成带 `via` 的打出。
- **数字**（`digits.py`）：0–9 模板读右侧总分（基线对齐去火星）、领袖剩余次数、手牌数、卡牌战力。
  总分用专用模板（`python hud/digits.py train-score cache/rec/score_train_labels.json`，四局录像人工核对的 17 帧、森林和北方营地两种棋盘、火盆背景），
  取最近的模板（以前前 3 个投票，模板少的 8 输给 0）；数字底下粘着的火星不并进字形，贯穿整个截取框的光带不算字。
  以前的总分模板混了战力字形和切坏的“3”，3 常读成 2 / 7 / 5，8 读成 0：2026-10-01 北方营地棋盘那局把第二、三局比分读成 100:105（实际 108:105）。
  战力：截取框按**同排牌高**定位（同一排的牌一样大；单张估出的高度跟卡图构图有关，猫学派猎魔人偏小 16%，`board.row_heights`）；
  数字高约框高 0.4，护盾金光贴在数字下面连成的高字形只留顶部重新切，按顶端对齐去碎片（`power_glyphs`）；颜色只看字形像素（`glyph_color`：
  白 = 基础战力，但要字形真像基础战力的数字；绿 > 基础、红 < 基础）；读不准时截取框在小范围内挪几次取最吻合的。
  模板用人工标注的场上牌训练（`python hud/digits.py train-power cache/rec/power_train_labels.json`，两局 238 张），
  评估用另一批（`帧目录/power_truth.json`，`python hud/eval_power.py 帧目录`）：真人局 78 张读对 77（改之前 67%）。
  和总分凑和（`timeline.joint_powers`）只在第一候选正好凑上、或只改一张牌就能唯一凑上时采用（以前动态规划硬凑会把对的 20 改成 38）。
- **护盾**（`detect.shield`）：有护盾的牌整张泛金光、左下图标列有一个带深色圈的橙色圆点；金光也可能是神赐 / 增益动画 / 金色卡框，只认圆点（2026-10-01 真人局 2500 张场上牌人工核对，单帧错 5–6 张，都是孤立的一帧）。导出时每一步之前 2 秒内整排对得上的帧都读到同样的有 / 没有，才写改战力 `+盾` / `-盾`；卡面自带护盾的落地就算有，落地 4 秒内是动画不看。
- **换排**：同一方同名牌 4 秒内一离一进、排不同 = 移动（猫学派猎魔人回合结束换排）。
- **按卡面能力解释画面变化**（`export.py` 的 `M_*` 正则；HUD 本质上是记牌局：只记玩家主动做的——打出、领袖、指令、目标；自动发生的交给对局簿引擎）：
  抓捕（薇歌的嘴套：我方单位离场、对方出现同名牌 = 嘴套的目标）、转变（杜度：消失后原排出现敌方单位的同名牌 = 杜度的目标）、
  计时生成（千里镜：拥有者第 N 个回合结束时出现部署时所选单位的同名牌 → 带出，并反推千里镜的目标）、随之生成（伊达兰）、
  回合结束换排（猫学派猎魔人，对局最后一帧也算回合结束）、回合中途换排（场上有“指令：将 1 个单位移至另一排”且这回合没用过 → 记指令；
  没有而这回合对方领袖次数在减少 → 记领袖，不超过减少的次数）、我方回合对方单位离场而这回合打出的牌没有目标效果 → 我方带伤害 / 对决指令的单位用了指令、
  卡面点名的衍生牌（布朗温）→ 由点名它的牌带出。
- **卡面写明的来源**（`export.refers` / `text_source`）：进场 / 展示的牌，同一回合 15 秒内（要选牌的 20 秒）同一方打出的牌、或场上的牌的指令 / 剧情章节，
  卡面“生成 / 召唤 / 从某处打出”它（创造：同一回合 45 秒内）——点名、类别（“炼金”牌）、关键词（会师单位）、墓场里的（非中立、铜色）单位、展示后选的（幻觉）；
  触发条件（“每打出 1 张炼金牌”“若手牌中有……”）不算；每个来源按卡面张数封顶，剧情每章只触发一次、而且要刚打出过推进剧情的那类牌（德鲁伊）。
  动作按第一个动词：召唤 → summon，生成 → spawn（Y），从牌组 / 墓场打出 → 带 via 的打出。
  墓场能力（乌鸦之母：己方打出炼金牌时从墓场召唤自身）、战术牌离场 = 用了战术（衔尾蛇面具生成的乌鸦算它带出）、
  小局结束时场上带坚韧的牌下一小局开头“进场” = 留场（不记）。对方领袖技能卡面生成并打出的（战斗狂热 → 致幻菌菇）、这回合对方领袖次数在减少 → 记领袖。
  “从手牌打出”（马格尼师）是单独打出，不算带出；“创造并打出对方阵营的铜色牌 / 对方起始牌组的单位牌”（帝国外交、买通）、“检视己方牌组顶端 3 张并打出其中 1 张”（军事会议）都认，创造（三选一）给 20 秒。
  对方领袖技能生成并打出的单位（战术决策 → 莫尔凡·符里斯）同样按领袖次数记领袖 + 带 via 的生成。
  对方一回合里唯一的进场又没有卡面来源，可能是展示框没认出的特殊牌带出的（弗蕾雅的祝福 → 鸦母布道者），不猜，照常问。
  2026-10-01 北方营地棋盘一局（对斯凯利格乌鸦）：“打出还是带出”待确认 10 条 → 0。
- **按机制补目标**：伤害 / 摧毁（特殊牌前后 8 秒、单位部署后 6 秒内，卡面那一方唯一离场的单位）、
  增益并解除锁定（玛哈坎麦酒 → 场上唯一被锁定的单位）、皇家激励后 3 秒内某单位神赐生成了牌 → 目标是它。
  我方领袖黄光而次数没变、总分没涨：只会加分的领袖（皇家激励）= 取消了，不再问。黄光常在加分之后才拍到，黄光前的总分取开始前 1.5 秒以前的。
  领袖目标：免疫的不算，涨得最多的要比第二名多 2 以上；黄光前才落地的按卡面基础战力算增益。
  我方回合对方总分掉了、没有单位离场、这几秒没有带目标的动作 → 我方能用的“指令：重置 / 伤害”单位用了指令（几张都能用时，目标正好回到基础战力 = 重置），目标是战力掉得最多的对方单位（赤红男爵）。
  推目标：卡面写明友军 / 敌军的按卡面；“移除其锁定”不算锁定；正好等于卡面数值的优先；免疫的不算；同一核对点几张牌不抢同一个目标；
  对方几张带目标的牌 4 秒内连着结算（三张炼金牌），每张只看自己那一段总分变化前后的战力，推出来的也标“拿不准”进清单。
- **特殊牌**：卡组里只有 1 张、“离手”之后 2 分钟（本小局内）手牌区照样认得出（出现率不低于之前的一半）= 识别闪烁，不算打出；
  前后 8 秒手牌数减少的次数都被同时从手牌落地的单位用掉了（之前在手牌区认出过的才算；手牌数读数变多说明读错，不用）= 不算打出。
  手牌数推特殊牌时，落地的单位之前从没在手牌区出现过、特殊牌卡面又是“从牌组打出”（水路突袭），掉 0.2 就够。
  手牌区检测至少 6 票（`timeline.HAND_MIN_V`；假检测 4–5 票，真手牌中位数 36 票）。
