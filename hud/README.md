# 对局 HUD

扫描游戏画面，完整记录对局：双方每排的牌、进场 / 离场 / 移动、从手牌打出 / 召唤 / 生成、对方特殊牌、领袖技能、停牌、每手之后的双方总分；置顶小窗实时显示，一键导出对局簿能直接导入的 v2 对局代码。

只截屏幕上公开显示的画面：不改游戏、不读内存、不抓网络包。

## 安装（一次）

```bash
python -m pip install --user opencv-python mss numpy Pillow
node hud/export_cards.js
python hud/build_db.py
```

`build_db.py` 从 gwent.one 下载卡图（约 130 MB）并建特征库，都在 `hud/cache/`（不提交）。卡牌数据更新（补丁、新牌）后重跑这两步。网络走 `HTTPS_PROXY`。

我方卡组：把卡组代码（`#GWDECK v2 …`）或对局簿备份文件路径写进 `hud/deck.txt`，我方就只认卡组里的牌（外加衍生牌），手牌区的误识别进不来。

## 实时使用

```bash
python hud/hud.py
```

- 游戏用**窗口模式**（程序按进程自动找 Gwent.exe 的窗口，窗口移动了也跟着走）。游戏窗口别被其他窗口挡住；小窗自己默认不出现在截图和录屏里。
- 小窗：比分和小局、对方已出的牌（解牌标红、召唤/生成标灰）、场面时间线。
- “导出对局代码”：复制对局簿 v2 代码，到对局簿“导入对局”粘贴，直接复盘。召唤记录带 `x.hud` 标记、离场 / 移动写成备注，方便核对。
  默认把画面上读到的每个单位战力（连续两帧一致）写成改战力记录，对局簿里的场面就是实际场面；`--no-sync` 关掉（核查推算引擎规则时用）。
- `--save-frames` 把扫描过的画面存下来（一局几百 MB），给离线分析、调参数用。

## 离线分析

```bash
python hud/record.py 40                          # 录游戏窗口（全分辨率，只存有变化的帧）
python hud/video_frames.py 录屏.mp4               # 或者从录屏视频抽帧（iPad 4:3 也行）
python hud/export.py hud/cache/rec/<目录> 20261001 --jobs=4 --deck=hud/deck.txt --sync-power
node hud/replay_check.js hud/cache/rec/<目录>/game_v2.txt               # 喂给对局簿推算引擎，逐局出偏差报告
python hud/power_train.py hud/cache/rec/<目录>                           # 用白色数字重新训练战力模板
python hud/compare.py hud/cache/rec/<目录>/game.json 对局簿备份.json    # 和对局簿手记的同一局比较
python hud/timeline.py hud/cache/rec/<目录> 20261001                  # 只看时间线；人机对局会和游戏日志核对 AI 出牌
```

## 准确率（2026-10-01）

- 电脑人机一局喂给对局簿推算（`node hud/replay_check.js 帧目录/game_v2.txt`，同步战力）：三局推算 9:19 / 27:9 / 76:32，真实 9:19 / 28:9 / 69:26。

- 电脑人机一局（全分辨率录像）：游戏日志里 AI 的 16 张出牌全部认出；三局比分 9:19 / 28:9 / 69:26。
- iPad 录屏两场（和对局簿手记对比）：对局簿记的 63 张打出认出 59 张（94%），多记 5 张；漏的主要是对方特殊牌（iPad 没有右侧展示）。

## 做法

- **认牌**（`matcher.py` `board.py`）：SIFT 特征比对 gwent.one 卡图。每个匹配点按它在卡图上的相对位置和缩放反推卡牌中心和高度，按中心聚成一张张牌（相邻同名牌能拆开）；高度大的是手牌，其余按中心高度分四排。
- **时间线**（`timeline.py`）：按“排 × 牌名”记张数，带迟滞（进场要连续两次看到，离场要连续三次、至少 2.5 秒看不到）；同排同名牌离场后 40 秒内又出现当作识别闪烁；模糊的覆盖界面（调度、墓场、选牌）和读不到总分的帧跳过；一大半牌同时消失且出现过模糊画面 = 小局结束。
- **打出还是召唤**：对方靠右侧展示框（对方打出的牌会放大展示不到 1 秒，`hud.py` 的展示线程每 0.15 秒看一次；特殊牌只能靠它）；我方可收集单位 / 神器落地算打出，手牌里消失的特殊牌算打出特殊牌；同排同名复制、刚打出“召唤”牌后几秒内进场的记成带 `via` 的召唤。
- **数字**（`digits.py`）：0–9 模板读右侧总分（基线对齐去火星）、领袖剩余次数、手牌数、卡牌战力（白色 = 基础战力；绿 > 基础、红 < 基础约束候选；再和总分凑和，`timeline.joint_powers`）。
- **离场原因、效果目标**（`export.py`）：离场前后墓场张数图案 / 手牌数的变化；打出前后各单位战力的变化按卡面数值挑目标。我方总分后面的蓝旗 = 我方回合；小局最后一方连续行动 = 另一方停牌。
- **位置参数**（`layout.py`）：按画面比例切换，电脑 16:9、iPad 4:3。

## 还没做 / 已知问题

- 战力数字：白色直接取基础战力；绿 / 红读数再用“一方战力之和 = 总分”一起纠错（凑得上的帧：对方约 60%、我方约 30%，我方常有高亮的牌没认出）。护甲和状态图标没做。
- 离场原因：看墓场张数的字形图案（斜体数字认不准，只看变没变）和手牌数，分成摧毁 / 回手 / 放逐；吞噬没单独区分。
- 效果目标：只推“部署”和特殊牌里写明“对 / 使 / 摧毁 / 锁定 N 个”的；关键帧里有牌没认出来时推不出。
- 对方最后一次领袖（次数标牌只在对方回合显示，用完就不见）看不出来；对方领袖是哪个技能不知道。
- 墓场、选牌界面里的信息（从牌组拉出的是哪张）还没用上。
- iPad：没有展示框、我方领袖和回合位置未标定。
